# Requisitos

| ID | Requisito | Estado | Evidencia |
|---|---|---|---|
| ARQ-01 | Separación cliente-servidor y mismo origen | hecho | `server.js` sirve `frontend` y el cliente usa `/api`. |
| ARQ-02 | Capas del backend: API, lógica y datos | hecho | `server.js`, `userModel.js` y `database.js`. |
| ARQ-03 | Capas del frontend: presentación y comunicación | hecho | HTML separado de `frontend/js/api.js` y `frontend/js/auth.js`. |
| RF-01 | Registro de usuario local | hecho | `POST /api/registro` y `UserModel.create`. |
| RF-02 | Confirmación de cuenta por correo | parcial | `mailer.js`, token de confirmación y `/api/auth/verify/:token`; queda por verificar el envío real. |
| RF-03 | Inicio de sesión local | hecho | `POST /api/login`, comprobación del estado y del hash. |
| RF-04 | Inicio de sesión con OAuth | hecho | Passport Google en `server.js` y callback. |
| RF-05 | Cierre de sesión | hecho | `POST /api/logout` llama a `deleteToken`. |
| RF-06 | Mantenimiento de la sesión entre recargas | hecho | Token en `localStorage` y consulta de `/api/session`. |
| RF-07 | Listar usuarios (administrador) | hecho | `GET /api/users` está protegido por sesión y rol. |
| RF-08 | Comprobar si un usuario está activo (administrador) | pendiente | Existe `UserModel.isActive`, pero no se ha encontrado un endpoint administrativo para esta operación. |
| RF-09 | Eliminar usuario | hecho | `DELETE /api/users/:email` está protegido por sesión y rol. |
| RF-10 | Creación del primer administrador | pendiente | No se ha encontrado en el repositorio un mecanismo verificable para crear el primer administrador. |
| RF-MVP-Diario | Diario íntimo: crear, listar y borrar entradas propias con título opcional | hecho | `POST`, `GET` y `DELETE /api/diario` protegidos por `authMiddleware`; `diaryModel.js`, `diaryService.js` y `diaryRouter.js`; título opcional de máximo 50 caracteres; 40 pruebas unitarias con dobles. |
| RF-MVP-Diario-Frontend | Integración frontend del diario: guardado, historial “Ecos”, lectura y borrado | hecho | `diario.html` muestra el título o un extracto de 40 caracteres, abre el eco completo y permite eliminarlo; `api.js` centraliza `crearEntradaDiario(text, title, vinylId)`, `listarDiario` y `eliminarEntradaDiario`. El formulario incorpora el selector de vinilos y la lectura muestra el mini-vinilo enlazado. |
| RF-MVP-Muro | Muro de debates: crear y borrar (solo administradores), listar y reaccionar con toggle | hecho | `debateModel.js`, `debateService.js`, `debateRouter.js`; `POST /api/debates` y `DELETE /api/debates/:id` con `authMiddleware` e `isAdminMiddleware`; `GET /api/debates`; `POST /api/debates/:id/react`; tres reacciones (`profundo`, `melancolico`, `rompeEsquemas`) como arrays de `ObjectId` y etiquetas exactas en `debateConstants.js`; `coverImageUrl` opcional con validación `http`/`https`; `isAnonymous` booleano con `authorEmail: null` cuando es anónimo. La suite cubre modelo, servicio y router con dobles de repositorio y autenticación. |
| RF-MVP-Muro-Frontend | Integración frontend del muro: tarjetas dinámicas, portadas, autor recortado, borrado y reacciones autenticadas | hecho | `muro.html` carga `GET /api/debates` mediante `api.listarDebates()`, envía reacciones con `api.reaccionarDebate(id, reaction)` y borra con `api.eliminarDebate(id)`; renderiza `coverImageUrl` con placeholder de respaldo, muestra el autor sin dominio o “Publicado por Anónimo” y conserva las clases CSS, el efecto de aura, el canvas y los estilos de scroll. Las tarjetas y el modal de lectura muestran el mini-vinilo cuando el debate tiene `vinyl`. |
| RF-MVP-Muro-Lectura | Reflexiones largas colapsadas y modal de lectura profunda | hecho | `crearTarjeta` recorta con `...` el contenido de más de 250 caracteres y añade “Leer más”; la tarjeta y el botón abren `readingModal`, que muestra el texto completo con estética glassmorphism y acentos dorados. Se cierra con “X”, backdrop o `Escape` y restaura el scroll previo. Los clics en reacciones y papelera no abren la lectura. |
| RF-MVP-Muro-Notificaciones | Avisos del muro con desvanecimiento automático | hecho | `mostrarEstado` usa la clase `is-visible` y `setTimeout` de 3,5 s más una transición de 350 ms; carga, error de carga y muro vacío son persistentes. |
| RF-MVP-Muro-Admin | Botón flotante y diálogo de administración para crear reflexiones | hecho | `muro.js` construye el FAB con el lápiz del Diario, el diálogo y las papeleras solo si `obtenerUsuarioActual()` devuelve rol `admin`; para un oyente no hay nodos de administración en el DOM. El diálogo incluye la casilla “Publicar como anónimo” y el selector de vinilos de El Archivo, el contenedor no tiene scroll propio y solo el textarea usa el scrollbar dorado. `api.crearDebate(title, content, coverImageUrl, isAnonymous, vinylId)` envía `POST /api/debates` y el backend responde `403` si el rol no es administrador. |
| RF-MVP-Muro-Autor | Autor visible sin dominio de correo y anonimato opcional | hecho | El router devuelve el autor sin dominio y, si `isAnonymous` es `true`, fuerza `authorEmail: null`; `muro.js` muestra el nombre recortado o “Publicado por Anónimo” y el diálogo administrativo permite marcar la casilla. |
| RF-MVP-Roles | Gestión de roles `usuario` y `admin`; `editor` documentado pero no implementado | hecho | `userModel.js` usa `usuario` por defecto y `adminMiddleware.js` solo autoriza `role === 'admin'`. El rol `editor` se documenta como intención futura, pero no se asigna ni se comprueba en el MVP (YAGNI). |
| RF-MVP-Auth-Redirect | Redirección posterior al login y al registro | hecho | El login de `index.html` y el callback de Google redirigen a `muro.html`; el registro intenta iniciar sesión automáticamente y, si la cuenta queda pendiente de verificación, muestra el aviso sin crear una sesión ficticia. |
| RF-MVP-Muro-Seed | Script de datos de prueba para el muro | hecho | `backend/seedDebate.js` y `npm run seed`: crea un debate sobre el duende, Camarón y el consumo musical con portada flamenca, es idempotente por título, completa la portada si faltaba y resuelve un autor administrador o un autor técnico. |
| RF-MVP-Velo | El Velo: pista diaria, respuesta ciega y revelación tras la reflexión | hecho | `veloTrackModel.js`, `veloService.js` y `veloRouter.js`; `GET /api/velo/today` devuelve exclusivamente `audioUrl` sin participación y la pista completa con reflexiones después; `POST /api/velo/today/reflect` valida y recorta un texto de 1 a 5000 caracteres, guarda una única reflexión por usuario y responde `409` ante un segundo envío; `releaseDate` es única y se normaliza a medianoche UTC. |
| RF-MVP-Velo-Frontend | Estados ciego y revelado, reproductor y muro de voces de El Velo | hecho | `velo.html` y `velo.js`; el estado ciego solo monta el reproductor y el textarea, sin insertar título, artista, portada ni vinilo; el revelado muestra portada, metadatos, fecha, reproductor, mini-vinilo enlazado y reflexiones con la propia marcada como “Tu reflexión” y las demás como “Voz NN”. Los audios directos usan `<audio controls>` y los enlaces de YouTube, Spotify, SoundCloud, Vimeo y Bandcamp se convierten en iframes embebibles. |
| RF-MVP-Velo-Admin | Panel de encolado de pistas de El Velo para administradores | hecho | `admin.html` y `admin.js` incorporan “La Cola del Velo”; `POST`, `GET` y `PUT /api/velo/tracks` exigen `authMiddleware` e `isAdminMiddleware`; el formulario permite enlazar un vinilo con el selector compartido; el listado devuelve estado `past`, `today` o `future`, número de reflexiones y `vinyl` cuando existe; la edición bloquea pistas pasadas y responde `409` si la fecha ya está ocupada. |
| RF-MVP-Archivo-Busqueda | Buscar un disco por consulta libre o por artista y título, enriqueciendo la ficha con Last.fm y YouTube | hecho | `POST /api/archivo/buscar` valida la entrada, consulta `track.search` y `track.getInfo`, resuelve el audio y responde `{ disco, cached, created, stale }`; `archivoService.js` normaliza títulos, artistas, etiquetas, portadas y resúmenes; `201` si crea y `200` si reutiliza. |
| RF-MVP-Archivo-Cache | Cachear los discos en MongoDB y evitar llamadas externas repetidas | hecho | `Vinyl` con `catalogKey` única; `VinylRepository.findByCatalogKey` y `upsertByCatalogKey`; TTL configurable con `ARCHIVO_CACHE_TTL_DAYS`; `lastFmInfo.fetchedAt` alimenta la vigencia; un `upsert` atómico resuelve las carreras entre peticiones. |
| RF-MVP-Archivo-Cajones | Organizar la discoteca en cajones por género o artista | hecho | `GET /api/archivo/cajones` devuelve `{ agrupacion, total, cajones }`; cada cajón contiene `clave`, `etiqueta`, `total` y `vinilos`; la agrupación se construye en el servicio con etiquetas normalizadas y orden estable en español. |
| RF-MVP-Archivo-Detalle | Consultar la ficha completa de un disco | hecho | `GET /api/archivo/disco/:id` valida el `ObjectId`, devuelve la ficha con `lastFmInfo`, `catalogKey` y `playable`, y actualiza `lastAccessedAt`; `400` si el identificador no es válido y `404` si no existe. |
| RF-MVP-Archivo-Frontend | Integrar El Archivo en el frontend con cajones, ficha y reproductor | hecho | `archivo.html` y `archivo.js` presentan los cajones con portadas superpuestas, el conmutador por género o artista, los estados de carga, vacío, error y reintento, y el resumen de discos. `api.js` añade `listarCajonesArchivo(agrupacion)` y `obtenerDiscoArchivo(id)`. La navegación de Muro, Diario, El Velo y administración incorpora el enlace. |
| RF-MVP-Archivo-Detalle-Frontend | Abrir la ficha de un vinilo con carátula e información de Last.fm | hecho | Un clic simple abre el modal; `GET /api/archivo/disco/:id` se consume mediante `api.obtenerDiscoArchivo(id)` y el diálogo muestra título, artista, álbum, género, sinopsis, etiquetas, oyentes, reproducciones, duración, publicación y enlace a Last.fm. Se cierra con la «X», el fondo o `Escape`, atrapa el foco y permite reintentar. |
| RF-MVP-Archivo-Reproduccion | Reproducir el disco mediante un identificador de YouTube | hecho | El backend persiste `youtubeVideoId` validado y expone `playable`; los vinilos son `draggable="true"` y los eventos `dragstart`, `dragover`, `drop` y `dragend` alimentan un tocadiscos fijo. `archivo.js` carga la YouTube Iframe API en un reproductor oculto, inicia el vídeo y activa `@keyframes spin`; el control permite pausar y reanudar y avisa si no hay audio. |
| RF-MVP-Archivo-Vinculacion | Vincular vinilos cacheados con Muro, Diario y El Velo | hecho | `Debate`, `DiaryEntry` y `VeloTrack` incorporan `vinylId` opcional con `ref: 'Vinyl'`; los servicios validan su existencia, los repositorios pueblan la ficha y los routers añaden `vinyl` y `vinylId` solo cuando hay vínculo. En Muro y Velo el enlace lo controla un administrador; en Diario el usuario adjunta un vinilo a su propio eco. |
| RF-MVP-Archivo-Selector | Buscar y seleccionar vinilos cacheados desde las publicaciones | hecho | `js/vinylPicker.js` reutiliza `GET /api/archivo/cajones?agrupar=artista` mediante `api.listarVinilosArchivo()` y filtra en cliente por título, artista, álbum o género. Se monta en el diálogo administrativo del Muro, en la cola del Velo y en el formulario del Diario, con estados de carga, error, vacío y limpieza del vínculo. |
| RF-MVP-Archivo-Reproductor-Global | Mini-vinilo y tocadiscos global reutilizables | hecho | `js/vinylPlayer.js` pinta un mini-vinilo en tarjetas y modal del Muro, lectura del Diario y estado revelado de El Velo. El clic o el arrastre abren un dock fijo que carga la YouTube Iframe API bajo demanda, reproduce el `youtubeVideoId`, permite pausar, reanudar y cerrar, y avisa cuando el vinilo no tiene escucha. `js/vinilos.css` centraliza los estilos compartidos. |
| RNF-01 | Persistencia en una base de datos real | hecho | Mongoose conecta con MongoDB y `User` persiste los usuarios. |
| RNF-02 | Secretos fuera del código y .env.example | hecho | `.env.example` declara los nombres y el workflow usa secretos de GitHub. |
| RNF-03 | Hash seguro de contraseñas | hecho | `bcrypt.hash` y `bcrypt.compare` en `userModel.js`. |
| RNF-04 | Rutas protegidas por sesión y rol | hecho | `authMiddleware` e `isAdminMiddleware` protegen las rutas privadas. |
| RNF-05 | Despliegue en cloud con URL pública | parcial | Hay workflow y configuración de App Engine; la URL pública operativa queda por verificar. |
| RNF-06 | Pruebas unitarias de la lógica (5 o más) | hecho | Suites de Jest para Diario, Muro, El Velo y El Archivo, con dobles de repositorio, autenticación y red. La Tarea 7 ajusta las pruebas de modelo para las nuevas referencias a `Vinyl`; la ejecución completa posterior a la incorporación de El Archivo y de los vinilos transversales queda pendiente de verificación local. |
| RNF-07 | Manejo de errores con feedback al usuario | hecho | Las rutas devuelven mensajes y `api.js` propaga errores al frontend. |
| RNF-08 | Registro de actividad (log) | hecho | Winston y Morgan se configuran en `logger.js` y `server.js`. |
| RNF-09 | Proteger las cuotas de Last.fm y YouTube y no exponer secretos | hecho | Las tres rutas de El Archivo exigen `authMiddleware`; las claves `LASTFM_API_KEY` y `YOUTUBE_API_KEY` solo se leen en el servidor; la caché persistente reduce el consumo; `.env.example` declara las variables sin valores reales. |
| RNF-10 | Tolerancia a fallos de proveedores externos | hecho | Los errores de dominio distinguen validación (`400`), no encontrado (`404`), configuración (`503`), timeout (`504`) y fallo de proveedor (`502`); una ficha caducada se sirve como `stale` si Last.fm no responde; un fallo de YouTube no impide guardar los metadatos culturales. |
